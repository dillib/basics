# Test Prep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Students paste homework/test questions (text and images) and get a study set: concepts first, their own questions with feedback, answers revealed only after an attempt, practice, a "Test me" mode and a readiness summary.

**Architecture:** A staged background pipeline in `server/test-prep/` (parse → group → prepare → verify) writes progressively into one `test_prep_sets` row; the client polls it. Model calls go through the existing router `server/llm.ts` (extended for images and thinking). Answer keys never leave the server except via `reveal` after an attempt. Progress lives in the browser.

**Tech Stack:** Express + TypeScript, Postgres (raw SQL via `db.execute(sql…)` / idempotent `server/migrate.ts`), `@google/genai` (Gemini 2.5 Flash, multimodal), Inception Mercury via `llm.ts`, Jev via `server/intake.ts`, React + wouter + react-query + Tailwind/shadcn, vitest.

**Spec:** `docs/superpowers/specs/2026-10-09-test-prep-design.md`

## Global Constraints

- Limits per set: ≤ 30 questions, ≤ 10 images, ≤ 20,000 characters. Over limit → HTTP 422 with a message, never silent truncation.
- Rate limit: 10 new sets per visitor per hour, keyed by `clientIp` (`server/security.ts`).
- Images shrunk in the browser to longest side ≤ 1600 px, JPEG, before upload.
- Client polls `GET /api/test-prep/:id` every 1.5 s until `status` is `ready` or `failed`.
- Sets expire 30 days after `created_at`; purged at boot and daily.
- `GET` responses never contain keys, explanations, hints or verification details.
- `reveal` returns 409 unless the question has ≥ 1 attempt.
- Question types: `mc`, `tf`, `numeric`, `short`, `open`. `open` never gets right/wrong.
- Level from detected grade: grades 1–5 → `kid`, 6–12 → `teen`, otherwise `adult`.
- Spend tasks: `test_prep_parse`, `test_prep_group`, `test_prep_prepare`, `test_prep_verify`, `test_prep_grade`. Never blocked by the budget.
- Fixed copy: "Paste your homework or test questions, images too" · "Found {n} questions on {k} topics" · "Couldn't read this one, type it in" · "Check this one with your teacher" · "We couldn't find questions in that. Want to learn a topic instead?" · "This looks like a set of questions. Prep for a test instead?" · tabs "Learn a topic" / "Prep for a test" · modes "Learn" / "Test me".
- No prices, no testimonials; all generated text follows the kid/teen rules in `server/ai.ts` and passes `lint` (`server/safety.ts`).

## Review Focus

1. **A deploy restarts the server mid-pipeline** (deploys are frequent) → the set must not stay stuck in `preparing`: a non-terminal set whose `updated_at` is > 3 min old is resumed from its current stage on the next `GET`. Test in Task 7.
2. **Numeric answers in different forms** (`3/4`, `0.75`, `.75`, `x = 4`, `4 cm`) → graded as the same value when equal. Test in Task 5.
3. **Multiple-choice answered by letter or by text** (`b`, `B)`, `(b)`, or the option's text) → all accepted. Test in Task 5.
4. **A paste that is only screenshots, no text** → questions are read from the images. Test in Task 3.
5. **An unknown or expired set id** (old bookmark, cleared device) → 404, and the client shows "This set has expired or doesn't exist" with the paste box, not an error. Tests in Tasks 7 and 9.
